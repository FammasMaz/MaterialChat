# Bounded Gemini speech backend

## Integration

`GeminiTtsBackend(player = yourPlayer).speak(text, settings, key): Flow<TtsEvent>` generates one utterance per collection. Supply the existing `AssistantVoiceSettings` with explicit `geminiModel` and `geminiVoice`. Retrieve/decrypt the dedicated encrypted key immediately before collection. The backend does not persist or log it. A JVM String cannot be reliably erased; do not retain the returned cold Flow longer than needed.

`GeminiPcmPlayer.play(pcm, sampleRate)` is the injectable playback boundary, not an installed Android player. Implementations must play signed little-endian 16-bit mono PCM, suspend until audible completion, and stop/release playback before returning on cancellation. The buffer is borrowed and zeroed when playback returns. Serialize collections externally if sharing a physical player. No Android manager, ViewModel, overlay or preference integration is changed here.

Collecting emits Started immediately before calling the player and Completed after it returns. Cancel the collecting Job to stop; CancellationException propagates (no Stopped event after cancellation). Errors emit a fixed, sanitized Error per failure category. Internal synthesis/playback deadlines emit a timeout Error; cancellation of the collecting job still propagates. A cancellable transport and player can be injected for tests.

Limits: 4,000 UTF-16 text characters, 512 key characters, 64 voice-name characters, 4,000,000 response bytes, 2,880,000 decoded PCM bytes (60 seconds at 24 kHz), 60-second generation and 70-second playback deadlines. Legacy generateContent responses require exactly one STOP candidate. Interactions responses require completed status and model_output steps containing inline audio content. Both require one or more audio blocks. Parts are concatenated in order with an aggregate decoded bound; each must contain valid base64, nonempty even-length PCM and explicit 24-kHz audio/l16 MIME. Text/thought parts are ignored only when valid audio exists. Unsupported inline formats and unknown nonaudio parts reject the entire response. Temporary decoded chunks, response bytes and borrowed playback PCM are wiped. No WAV guessing, resampling, redirects, retries, logging interceptors or disk cache. The dedicated OkHttp client cancels its owned Call when collection is cancelled. Limits are application safety limits, not provider quotas.

## Official sources and supported scope

Google's [speech generation guide](https://ai.google.dev/gemini-api/docs/speech-generation), now served at [AI Studio speech generation](https://aistudio.google.com/docs/speech-generation), lists `gemini-3.1-flash-tts-preview` and `gemini-2.5-pro-preview-tts` alongside newer models. Google's [pricing page](https://aistudio.google.com/docs/pricing#gemini-2.5-flash-preview-tts) additionally lists `gemini-2.5-flash-preview-tts`. This backend explicitly accepts those three preview generateContent models; there is no automatic model default.

The same guide's audio-format/migration section documents older preview output as headerless `audio/l16` PCM, contrasting newer unary WAV output. The [generateContent REST reference](https://ai.google.dev/api/generate-content) describes contents, generationConfig, responseModalities, speechConfig/voiceConfig/prebuiltVoiceConfig, candidates and inlineData. Requests use `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent`, with the key in `x-goog-api-key`, never a URL query.

Gemini 3.8 Flash TTS (`gemini-3.8-flash-tts`) and Flash-Lite TTS (`gemini-3.8-flash-lite-tts`) instead use `POST https://generativelanguage.googleapis.com/v1beta/interactions`. The [official Interactions REST reference](https://aistudio.google.com/api-reference/interactions-api) confirms that endpoint and the completed `steps[].content[]` response envelope: model output steps have `type: "model_output"`; audio content has `type: "audio"`, `mime_type`, and base64 `data`, with optional `sample_rate` and `channels`.

The request contains the selected `model`, `store: false`, `input: [{"type":"user_input","content":[{"type":"text","text":"Hello"}]}]`, `response_format: {"type":"audio","mime_type":"audio/l16","sample_rate":24000}`, and `generation_config: {"speech_config":[{"voice":"Kore"}]}`. The speech guide explicitly documents `speech_config` (the generic reference currently calls this field `structured_speech_config`); this implementation follows the TTS-specific guide. It requests raw PCM explicitly because unary 3.8 defaults to WAV. The guide defines this PCM as signed little-endian 16-bit mono. Returned rate/channels, when present, must match 24000/1; absent metadata uses the explicitly requested documented defaults. WAV, compressed formats, URI audio, incomplete responses, and conflicting metadata fail closed. Legacy models retain their original protocol. The existing settings picker reads SUPPORTED_MODELS, so both 3.8 choices are exposed without changing UI files.

Google's [pricing table](https://aistudio.google.com/docs/pricing#gemini-3.1-flash-tts-preview) lists free input/output for 3.1 Flash TTS Preview; the [2.5 Flash section](https://aistudio.google.com/docs/pricing#gemini-2.5-flash-preview-tts) also lists free input/output. The [2.5 Pro section](https://aistudio.google.com/docs/pricing#gemini-2.5-pro-preview-tts) says free tier **not available**. Free-tier requests are marked as used to improve Google's products; paid-tier requests are marked No. Free does not mean unlimited or a guarantee of account access. [Rate limits](https://ai.google.dev/gemini-api/docs/rate-limits) vary by model/project/tier and should be checked in AI Studio; no universal numeric quota is baked into this backend. Send text only with informed user consent.

## Verification

Fourteen JVM JUnit tests pass with JDK17, `--max-workers=2 --no-daemon`, using `:app:testGithubDebugUnitTest --tests com.materialchat.assistant.voice.GeminiTtsBackendTest`. Tests inspect actual OkHttp serialized requests for all five models, including endpoint, authentication header, transcript, voice and explicit PCM response format; feed protocol-specific JSON response envelopes through the production transport/backend; reject malformed formats and incomplete envelopes; and verify owned HTTP cancellation for both 3.8 models. Existing legacy bounds, wiping, cancellation and sanitized-error tests remain. No credential, live synthesis, emulator, native playback or production UI verification was performed.

## Typed failures and documentation recheck

`GeminiTtsException.kind` distinguishes authentication (HTTP 401), permission (403), quota/rate limit (429), model unavailable (404), transport/service failures (other HTTP statuses or I/O), and invalid/unsupported audio. Messages are fixed; exceptions retain no provider body, URL, key or underlying cause. HTTP bodies are not parsed for diagnostics, so ambiguous statuses (for example an invalid API key returned as 400) remain transport/service failures rather than guessing from provider text.

The cached official speech guide (`/tmp/gemini-speech.md`) and Interactions reference (`/tmp/gemini-interactions.md`) supplied the protocol evidence. Documentation and mocked HTTP tests are not evidence of live account/model availability. No key or live synthesis request was used.
